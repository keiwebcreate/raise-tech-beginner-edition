# 要件定義書：トレロ風タスク管理アプリ

最終更新：2026-10-25

## 1. 概要

カンバン方式のタスク管理Webアプリ。ボードの中にリスト（列）を並べ、タスクをカードとして管理する。カードはドラッグ＆ドロップでリスト間を移動できる。

- 目的：講座課題。AIと一緒に要件定義からデプロイまでの流れを経験する。完成後はポートフォリオとして公開する
- 利用者：ユーザー登録をした個人。自分のタスクを管理する
- 締め切り：なし

## 2. 用語

| 用語 | 意味 |
|---|---|
| ユーザー | アカウント登録をした利用者 |
| ボード | プロジェクト1つ分の画面。ユーザーは複数のボードを持てる |
| リスト | ボードの中の縦の列（例：やること／作業中／完了）。コード上では `Column` と呼ぶ（Javaの `List` と名前がぶつかるため） |
| カード | タスク1件。どれか1つのリストに属する |

## 3. 機能要件

### 3.1 Must（完成に必須）

| ID | 機能 | 内容 |
|---|---|---|
| M-01 | リスト追加 | ボードにリストを追加する。追加したリストは右端に並ぶ |
| M-02 | リスト名変更 | リストの名前を変更する |
| M-03 | リスト削除 | リストを削除する。中のカードも一緒に削除する（確認ダイアログを出す） |
| M-04 | カード追加 | リストの一番下にカードを追加する（タイトルは必須） |
| M-05 | カード編集 | カードのタイトルを変更する |
| M-06 | カード削除 | カードを削除する（確認ダイアログを出す） |
| M-07 | カード移動 | ドラッグ＆ドロップで、同じリスト内の並び替えと別のリストへの移動ができる |
| M-08 | データ保存 | すべての操作をMySQLに保存する。リロードしても状態が残る |
| M-09 | 公開 | AWSにデプロイし、URLでアクセスできる |

### 3.2 Should（ポートフォリオとして必要。今回の完成範囲に含める）

| ID | 機能 | 内容 |
|---|---|---|
| S-01 | ユーザー登録 | メールアドレスとパスワードで登録する |
| S-02 | ログイン／ログアウト | ログインしていないとボードを見られない |
| S-03 | アクセス制御 | 自分のボードだけを見たり操作したりできる |
| S-04 | ボード一覧 | 自分のボードを一覧表示する |
| S-05 | ボード追加・名前変更・削除 | ボードを管理する |
| S-06 | カード詳細 | カードをクリックすると詳細画面が開き、説明文・期限・ラベル色を設定できる |
| S-07 | 期限の表示 | 期限が近いカードと過ぎたカードを色で区別する |
| S-08 | 入力チェック | 空のタイトルや長すぎる文字列を受け付けず、エラーメッセージを表示する |
| S-09 | エラー表示 | 通信エラーやサーバーエラーが起きたら、画面にわかりやすく表示する |

### 3.3 Could（余裕があれば。今回の範囲外）

- リストのドラッグ＆ドロップによる並び替え
- カードの検索・絞り込み
- ボードの共有（メンバー招待）
- 自動テストとCI/CD（GitHub Actions）

### 3.4 やらないこと

- リアルタイム同時編集（ほかの人の操作が即座に画面に反映される機能）
- ファイルの添付
- スマートフォン専用アプリ（ブラウザで表示が崩れない程度の対応はする）

## 4. 画面一覧

| 画面 | URL（案） | 内容 |
|---|---|---|
| ログイン | `/login` | メールアドレスとパスワードを入力する |
| ユーザー登録 | `/signup` | アカウントを作る |
| ボード一覧 | `/boards` | 自分のボードを一覧表示し、追加・削除する |
| ボード | `/boards/:id` | リストとカードを表示する。メインの画面 |
| カード詳細 | ボード画面の上に開くモーダル | 説明文・期限・ラベルを編集する |

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| セキュリティ | パスワードはハッシュ化して保存する。通信はHTTPSにする。他人のデータはAPIからも取得できないようにする |
| 対応ブラウザ | Chrome・Edge・Safariの最新版 |
| 画面サイズ | PCでの利用が中心。スマートフォンでもレイアウトが崩れないようにする |
| 性能 | 操作から画面に反映されるまで1秒以内を目安とする |

## 6. 技術スタック

| 区分 | 技術 |
|---|---|
| フロントエンド | React（Vite） |
| バックエンド | Java 21 / Spring Boot |
| データベース | MySQL |
| 認証 | Spring Security（方式は設計の工程で決める） |
| インフラ | AWS（EC2 + RDS を想定。詳細は設計の工程で決める） |
| バージョン管理 | Git / GitHub |

## 7. 未決事項（設計の工程で決める）

- 認証方式（セッション方式かJWT方式か）
- ドラッグ＆ドロップに使うライブラリ
- AWSの詳しい構成（Reactの画面をEC2から配信するか、S3 + CloudFrontに分けるか、ドメインとHTTPS化の方法）
- テーブル設計とAPI設計
