# 要件定義書：トレロ風タスク管理アプリ

版：1.10（2026-11-01）。変更の履歴は 10章

## 1. 概要

カンバン方式のタスク管理Webアプリ。ボードにリスト（列）を並べ、タスクをカードとして管理する。カードとリストはドラッグ＆ドロップで並び替えられる。

- 目的：講座の課題。AIと相談しながら、要件定義からデプロイまでの流れを経験する。完成後はポートフォリオとして公開する
- 利用者：ユーザー登録をした個人。自分のタスクを管理する。ポートフォリオを見る人は、ゲストログインで試せる
- 締め切り：なし

### 1.1 前提条件と制約

**前提条件**（この要件が成り立つための条件）

| 項目 | 内容 |
|---|---|
| 作る人 | 講座の受講者1人が、AI（Claude Code）と相談しながら作る |
| 使う人 | 自分のタスクを自分で管理する個人。ほかの人とボードを共有しない（7章） |
| 使う場所 | PC のブラウザが中心（NA-02・NA-03） |
| メール | メールは送らない。確認メールとパスワードの再設定はない（7章。メールを送る仕組みは AWS の SES とあわせて検討する） |

**制約**（守らなければならない条件）

| 項目 | 内容 |
|---|---|
| 技術 | 講座の指定に従う：Java・Spring Boot・React・PostgreSQL・AWS（6章） |
| 費用 | AWS の無料枠の範囲だけで公開する（NO-01） |
| 規模 | 同時に使う人は10人ほど（NP-01）。データ量に上限を設ける（3.7） |
| 公開の時期 | AWS への公開（G-04）は、講座の AWS の講義を受けてから行う |

## 2. 用語

| 用語 | 意味 |
|---|---|
| ユーザー | アカウント登録をした利用者 |
| ゲストユーザー | 「ゲストとして試す」でログインした一時的な利用者 |
| ボード | タスク管理の画面。ユーザー1人が複数持てる（3.2） |
| リスト | ボードの中の縦の列（例：未着手／作業中／完了）。コード上では `Column` と呼ぶ（Javaの `List` と名前がぶつかるため） |
| カード | タスク1件。どれか1つのリストに属する |
| ラベル | カードに付ける色付きのタグ（例：仕事、買い物）。ユーザーごとに管理し、どのボードでも同じものを使う |

## 3. 機能要件

### 3.1 ユーザー・ログイン

| ID | 機能 | 内容 |
|---|---|---|
| U-01 | ユーザー登録 | メールアドレスとパスワードで登録する（入力ルールは下の表）。メールアドレスの重複は不可。登録が終わったら、自動でログインした状態でボード一覧へ進む |
| U-02 | 初期ボード作成 | 登録時にボード（「マイボード」）を1つ自動で作る。ボードには「未着手／作業中／完了」の3リストを用意する |
| U-03 | ログイン | メールアドレスとパスワードでログインする。失敗したときは「メールアドレスまたはパスワードが正しくありません」とだけ表示し、どちらが違うかは教えない |
| U-04 | ログアウト | ログアウトしてログイン画面に戻る |
| U-05 | アクセス制御 | ログインしていないとボードを見られない。他人のボード・リスト・カード・ラベルは、画面からもAPIからも見たり操作したりできない。他人のデータを指定されたときは「見つかりません」として扱う |
| U-06 | ゲストログイン | ログイン画面の「ゲストとして試す」でログインする。押すたびに新しい一時ユーザーを作り、サンプルのリスト・カード・ラベルが入ったボードを使える。ほかの人の操作とデータは混ざらない |
| U-07 | ゲスト表示 | ゲストでログインしている間は、画面のヘッダーに「ゲストモード：データはログアウトするか24時間たつと削除されます」と表示する |
| U-08 | ゲストデータの削除 | ゲストがログアウトしたら、そのデータをすぐに削除する。ログアウトせずに離れた場合は、作成から24時間たったゲストのデータを1時間ごとに自動で削除する |
| U-09 | 自動ログアウト | 何も操作しない時間が30分続いたら、ログアウトした状態になる。次の操作でログイン画面に戻す |
| U-10 | 回数制限 | 同じ接続元（IPアドレス）からのログインの失敗（退会・メールアドレスとパスワードの変更でのパスワード違いも含む）は15分に10回まで、ゲストの作成は1時間に10回まで、ユーザー登録（登録できたときと、登録済みで断ったとき）は1時間に10回まで。超えたら「しばらくしてから再度お試しください」と表示する |
| U-11 | 退会 | ヘッダーのメニューから退会できる（画面は `screen-design.md` W-08）。確認ダイアログでパスワードを入力して本人か確かめ、正しければアカウントとすべてのデータ（ボード・リスト・カード・ラベル）を削除する。削除したあとはログイン画面に戻り、「退会しました」と表示する。ゲストには表示しない（ログアウトでデータが消えるため） |
| U-12 | メールアドレスの変更 | ヘッダーのメニューから変更できる（画面は `screen-design.md` W-09）。新しいメールアドレス（入力ルールは下の表）と今のパスワードを入力し、パスワードが正しければすぐに変える（確認メールは送らない）。登録済みのアドレスには変えられない。変えたら、ほかのブラウザ・端末はログアウトさせ、今の画面はログインしたままにする。ゲストには表示しない（メールアドレスがダミーのため） |
| U-13 | パスワードの変更 | ヘッダーのメニューから変更できる（画面は `screen-design.md` W-10）。今のパスワードと新しいパスワード（入力ルールは下の表。確認のためにもう一度入力する）を入力し、今のパスワードが正しければ変える。変えたら、ほかのブラウザ・端末はログアウトさせ、今の画面はログインしたままにする。ゲストには表示しない |

入力ルール：

| 項目 | ルール |
|---|---|
| メールアドレス | メールアドレスの形式であること。254文字まで。大文字は小文字にそろえて保存する（`Taro@example.com` と `taro@example.com` は同じ人とみなす）。存在するアドレスかどうかの確認（確認メールの送信）はしない |
| パスワード | 8〜64文字。半角の英数字と記号のみ。英字と数字を両方含む、などの組み合わせのルールは付けない |

### 3.2 ボード

| ID | 機能 | 内容 |
|---|---|---|
| B-01 | ボード名 | ボード画面のヘッダーにボード名を表示する。クリックすると名前を変更できる（1〜50文字）。登録時のボードの初期値は「マイボード」 |
| B-02 | ボード一覧 | ログインしたら、自分のボードの一覧（ボード名のタイル）を表示する。並びは作った順。タイルを押すとそのボードを開く。ボードは URL（`/boards/{ID}`）で開くので、再読み込みやブックマークでも同じボードを開ける。ボード画面のヘッダーの「← ボード一覧」で一覧に戻る |
| B-03 | ボードの追加 | 一覧の「＋ ボードを追加」で、名前（1〜50文字）を入れて作る。新しいボードには「未着手／作業中／完了」の3リストを用意し、作ったらそのボードを開く |
| B-04 | ボードの削除 | ボード画面のヘッダーの「…」（スマートフォンの幅では ☰）から削除する。確認ダイアログを出し、中のリストとカードも一緒に消す。ラベルはほかのボードでも使うので残す。最後の1つも消せる（一覧には「ボードがありません」と追加のボタンだけを出す）。消したら一覧に戻る |

ラベルはユーザー単位のまま、全ボードで共通に使う。カードは同じボードの中のリストへだけ動かせる。

### 3.3 リスト

| ID | 機能 | 内容 |
|---|---|---|
| L-01 | リスト表示 | ボードにリストを左から順に並べて表示する |
| L-02 | リスト追加 | 名前（1〜50文字）を入力してリストを追加する。追加したリストは右端に並ぶ |
| L-03 | リスト名変更 | リストの名前を変更する |
| L-04 | リスト削除 | 確認ダイアログ（例：「このリストと中のカード3件を削除しますか？」）を出してから、リストと中のカードを削除する。リストは0個になってもよい |
| L-05 | リスト並び替え | ドラッグ＆ドロップでリストの順番を入れ替える |

### 3.4 カード

| ID | 機能 | 内容 |
|---|---|---|
| C-01 | カード追加 | リストの下の「＋ カードを追加」を押し、タイトルだけを入力して Enter で追加する。追加したカードはリストの一番下に並ぶ |
| C-02 | カード詳細 | カードをクリックすると詳細画面（モーダル）が開き、タイトル・説明文・重要度・緊急度・期限・ラベルを編集できる。「保存」ボタンでまとめて保存し、保存せずに閉じるときは確認する |
| C-03 | カード削除 | 確認ダイアログを出してから削除する。詳細画面の「カードを削除」と、カードの右上のゴミ箱（マウスを乗せたときと、キーボードでカードを選んだときだけ出る。ホバーできないスマートフォンの画面では出さない）から削除できる |
| C-04 | カード移動 | ドラッグ＆ドロップで、同じリスト内の並び替えと別のリストへの移動ができる |
| C-05 | 期限の表示 | カードに期限（例：10/30。年が違うときは 2027/1/5）を表示する。期限切れは赤、今日か明日が期限なら黄色にする。「今日」は利用者のブラウザの日付で判定する |
| C-06 | 重要度の表示 | カードの左端に色の帯を付ける（高＝赤、中＝黄、低＝灰色） |
| C-07 | ラベルの表示 | カードに付いているラベルを色付きで表示する |
| C-08 | 緊急度の表示 | 緊急度が「高」のカードにだけ「至急」の札（赤い文字＋赤い枠）を表示する。「中」「低」はカードには表示せず、カード詳細で確かめる |
| C-09 | 説明文の表示 | カードに説明文を3行まで表示する。3行を超えるときは「もっと見る」を押すと、カードの中で全文を開く。開いた状態は保存しない（再読み込みで閉じる） |

カードの項目：

| 項目 | 必須 | 内容 |
|---|---|---|
| タイトル | ○ | 1〜100文字 |
| 説明文 | | 2000文字まで。改行を反映して表示し、`http://`・`https://` で始まるURLはリンクにする（新しいタブで開く）。カードには3行まで表示する（C-09） |
| 重要度 | | 高・中・低。初期値は「中」。そのタスクがどれだけ大事か |
| 緊急度 | | 高・中・低。初期値は「中」。そのタスクをどれだけ急ぐか |
| 期限 | | 日付（時刻なし） |
| ラベル | | 複数付けられる |

### 3.5 ラベル

| ID | 機能 | 内容 |
|---|---|---|
| T-01 | ラベル管理 | ラベルを追加・名前変更・色変更・削除する。名前は1〜20文字で、同じユーザーの中で重複不可。色は用意した8色（`screen-design.md` 6章）から選ぶ |
| T-02 | ラベル付け | カード詳細画面で、カードにラベルを付けたり外したりする。1枚のカードに複数付けられる |
| T-03 | ラベル削除時の扱い | ラベルを削除すると、付いていたすべてのカードから外れる。カードは削除しない |

### 3.6 共通

| ID | 機能 | 内容 |
|---|---|---|
| G-01 | データ保存 | すべての操作をDB（PostgreSQL）に保存する。リロードしても状態が残る |
| G-02 | 入力チェック | 空のタイトルや長すぎる文字列などを受け付けず、エラーメッセージを表示する。画面側とサーバー側の両方でチェックする |
| G-03 | エラー表示 | 通信エラーやサーバーエラーが起きたら、画面にわかりやすく表示する |
| G-04 | 公開 | AWSにデプロイし、URLでアクセスできるようにする |

### 3.7 データ量の上限

いたずらでデータが増えすぎるのを防ぐため、全ユーザー（ゲストを含む）に次の上限を設ける。上限に達したら「リストは20個までです」のように表示する。数値は設定で変えられるようにする。

| 対象 | 上限 |
|---|---|
| ボード | 1ユーザーに10個まで |
| リスト | 1ボードに20個まで |
| カード | 1リストに100枚まで |
| ラベル | 1ユーザーに30個まで（1枚のカードには、すべてのラベルを付けられる） |

### 3.8 検索・絞り込み

ボードのカードを、文字と条件で探す。

| ID | 機能 | 内容 |
|---|---|---|
| S-01 | 文字の検索 | ヘッダーの検索欄に入れた文字を含むカードだけを表示する。対象はタイトルと説明文。大文字・小文字、全角・半角、ひらがな・カタカナの違いは同じとみなす（「pdf」で「ＰＤＦ」、「ちぇっく」で「チェック」が見つかる）。空白で区切ると、すべての言葉を含むカード。入力するたびに結果が変わる（日本語の変換中は変えない） |
| S-02 | 絞り込み | 「絞り込み」ボタンで、ラベル（「ラベルなし」も）・期限（期限切れ／今日・明日／それより先／期限なし。C-05 と同じ区切り）・重要度・緊急度を選ぶ。同じ種類の中は「どれか」、種類どうしと文字の検索は「すべて」に合うカードを表示する |
| S-03 | 絞り込み中の表示 | 条件に合わないカードは隠す。リストは合うカードが0枚でも表示し、枚数を「2 / 5」のように出す。ヘッダーの下に「5件中2件のカードを表示しています」と「条件をクリア」を出す。絞り込み中は、カードのドラッグ＆ドロップと追加はできない（隠れたカードがあると、並び順の位置が決まらないため）。リストの並び替えはできる |
| S-04 | 条件の保存 | 条件は URL に入れ、再読み込みしても残す。サーバーには保存しない |

## 5. 非機能要件

ID は節ごとの英字と番号：NA（全般）・NS（セキュリティ）・NP（性能）・NO（運用）・NT（テスト）。

### 5.1 全般

| ID | 項目 | 内容 |
|---|---|---|
| NA-01 | 時刻 | DBの日時はUTCで保存する。画面での日付の判定は利用者のブラウザの時刻を使う |
| NA-02 | 対応ブラウザ | Chrome・Edge・Safariの最新版 |
| NA-03 | 画面サイズ | PCでの利用が中心。スマートフォンでも表示が崩れず、リストを横にスクロールして見られる程度に対応する。スマートフォンでのドラッグ＆ドロップは必須にしない |

### 5.2 セキュリティ

Webアプリの代表的な脆弱性の一覧（OWASP Top 10）を一通りカバーする。

| ID | 攻撃・リスク | 対策 |
|---|---|---|
| NS-01 | パスワードの漏えい | BCryptでハッシュ化して保存する |
| NS-02 | 通信の盗み見 | 本番の通信はHTTPSにする |
| NS-03 | SQLインジェクション | Spring Data JPA を使い、SQLを文字列の連結で作らない |
| NS-04 | XSS | React の自動エスケープに任せ、`dangerouslySetInnerHTML` は使わない。説明文のリンク化は `http://`・`https://` で始まるものだけにする |
| NS-05 | CSRF | Cookie `XSRF-TOKEN` とヘッダー `X-XSRF-TOKEN` でトークンを照合する（`api-design.md` 2.3） |
| NS-06 | セッションの乗っ取り | ログイン状態はセッション方式で管理する。Cookie に HttpOnly・Secure・SameSite を付け、ログイン時にセッションIDを変え、無操作30分で切る |
| NS-07 | 他人のデータの操作 | 毎回所有者を確認し、他人のデータには404を返す（U-05） |
| NS-08 | パスワードの総当たり | IPアドレスごとの回数制限（U-10） |
| NS-09 | アカウントの大量作成・登録済みのメールアドレスの調査 | IPアドレスごとの回数制限（U-10。ゲストの作成とユーザー登録） |
| NS-10 | クリックジャッキングなど | セキュリティ関係のHTTPヘッダーを付ける（他サイトへの埋め込み禁止、HTTPSの強制、読み込めるスクリプトの制限など） |
| NS-11 | 内部情報の漏えい | エラーの詳細（スタックトレース）を画面やAPIのレスポンスに返さない |
| NS-12 | 秘密情報の漏えい | パスワードなどの秘密情報はコードやGitに書かず、環境変数で渡す。本番ではAWSのパラメータ管理機能に入れる |
| NS-13 | ライブラリの脆弱性 | GitHub の Dependabot で、使っているライブラリの脆弱性の通知を受ける |
| NS-14 | DBへの直接攻撃 | DBはインターネットに公開せず、アプリのサーバーからだけ接続できるようにする。アプリ用のDBユーザーには必要な権限だけを与える |

### 5.3 性能

| ID | 項目 | 内容 |
|---|---|---|
| NP-01 | 測る条件 | データ量が上限いっぱいのボード（リスト20個・カード2,000枚・ラベル30個）。同時に使う人は10人ほどと想定する |
| NP-02 | 目標 | ボードの表示（`GET /api/boards/{ID}`）は1秒以内。それ以外の操作（追加・保存・並び替えなど）は0.5秒以内 |
| NP-03 | 測り方 | AWSに公開した環境で、ブラウザの開発者ツール（Network タブ）でAPIの応答時間を見る |

### 5.4 運用

| ID | 項目 | 内容 |
|---|---|---|
| NO-01 | AWSの予算 | 無料枠の範囲だけ。AWS Budgets で、料金が発生しそうなときにメールが届くようにする。無料期間が終わったら、公開をやめるか構成を見直す |
| NO-02 | バックアップ | DBを1日1回バックアップし、7日分残す（7日前までの状態に戻せる）。RDSを使う場合は自動バックアップ、EC2にPostgreSQLを置く場合は `pg_dump` で行う |
| NO-03 | ログ | 残すもの：エラー（500の原因）、ログインの成功・失敗、回数制限の発動、ユーザー登録・退会・メールアドレスとパスワードの変更、すべてのAPIのアクセス（日時・URL・ステータス・処理時間）。ユーザーはIDで記録する |
| NO-04 | ログに残さないもの | パスワード、CSRFトークン、セッションID、メールアドレス、カードなどの中身 |
| NO-05 | ログの保存期間 | 14日。本番は CloudWatch Logs に送る |

### 5.5 テスト

| ID | 対象 | 方法 |
|---|---|---|

## 9. 受け入れ基準

「この結果になれば、その要件はできている」と判断する条件。番号（AC-xx）は足した順の通し番号で、あとから足したものは表の途中でも次の番号にする。公開の前の手動のテスト（NT-03）で、上から順に確かめる。とくに書いていなければ、登録済みのユーザーでログインした状態から始める。

### 9.1 ユーザー・ログイン

| No. | 対象 | 操作・条件 | 期待する結果 |
|---|---|---|---|
| AC-01 | U-01・U-02 | 新しいメールアドレスと、ルールに合うパスワードで登録する | ログインした状態でボード一覧が開き、「マイボード」がある。開くと「未着手／作業中／完了」の3リストがある |
| AC-02 | U-01 | 登録済みのメールアドレス（大文字・小文字だけ違うものも）で登録する | 「このメールアドレスは登録済みです」が出て、登録されない |
| AC-03 | U-01 | 7文字のパスワード、または確認の欄と違うパスワードで登録する | 「パスワードは8〜64文字の半角英数字・記号で入力してください」または「パスワードが一致しません」が出る |
| AC-04 | U-03 | 正しいメールアドレスとパスワードでログインする | ボード一覧が開く |
| AC-05 | U-03 | パスワードを間違える。登録されていないメールアドレスでも試す | どちらも「メールアドレスまたはパスワードが正しくありません」だけが出る |
