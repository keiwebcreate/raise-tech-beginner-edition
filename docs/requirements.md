# 要件定義書：トレロ風タスク管理アプリ

最終更新：2026-10-25

## 1. 概要

カンバン方式のタスク管理Webアプリ。ボードにリスト（列）を並べ、タスクをカードとして管理する。カードとリストはドラッグ＆ドロップで並び替えられる。

- 目的：講座の課題。AIと相談しながら、要件定義からデプロイまでの流れを経験する。完成後はポートフォリオとして公開する
- 利用者：ユーザー登録をした個人。自分のタスクを管理する。ポートフォリオを見る人は、ゲストログインで試せる
- 締め切り：なし

## 2. 用語

| 用語 | 意味 |
|---|---|
| ユーザー | アカウント登録をした利用者 |
| ゲストユーザー | 「ゲストとして試す」でログインした一時的な利用者 |
| ボード | タスク管理の画面。ユーザー1人につき1つ |
| リスト | ボードの中の縦の列（例：未着手／作業中／完了）。コード上では `Column` と呼ぶ（Javaの `List` と名前がぶつかるため） |
| カード | タスク1件。どれか1つのリストに属する |
| ラベル | カードに付ける色付きのタグ（例：仕事、買い物）。ユーザーごとに管理する |

## 3. 機能要件

### 3.1 ユーザー・ログイン

| ID | 機能 | 内容 |
|---|---|---|
| U-01 | ユーザー登録 | メールアドレスとパスワードで登録する（入力ルールは下の表）。メールアドレスの重複は不可。登録が終わったら、自動でログインした状態でボード画面へ進む |
| U-02 | 初期ボード作成 | 登録時にボードを1つ自動で作る。ボードには「未着手／作業中／完了」の3リストを用意する |
| U-03 | ログイン | メールアドレスとパスワードでログインする。失敗したときは「メールアドレスまたはパスワードが正しくありません」とだけ表示し、どちらが違うかは教えない |
| U-04 | ログアウト | ログアウトしてログイン画面に戻る |
| U-05 | アクセス制御 | ログインしていないとボードを見られない。他人のボード・リスト・カード・ラベルは、画面からもAPIからも見たり操作したりできない。他人のデータを指定されたときは「見つかりません」として扱う |
| U-06 | ゲストログイン | ログイン画面の「ゲストとして試す」でログインする。押すたびに新しい一時ユーザーを作り、サンプルのリスト・カード・ラベルが入ったボードを使える。ほかの人の操作とデータは混ざらない |
| U-07 | ゲスト表示 | ゲストでログインしている間は、画面のヘッダーに「ゲストモード：データはログアウトするか24時間たつと削除されます」と表示する |
| U-08 | ゲストデータの削除 | ゲストがログアウトしたら、そのデータをすぐに削除する。ログアウトせずに離れた場合は、作成から24時間たったゲストのデータを1時間ごとに自動で削除する |
| U-09 | 自動ログアウト | 何も操作しない時間が30分続いたら、ログアウトした状態になる。次の操作でログイン画面に戻す |
| U-10 | 回数制限 | 同じ接続元（IPアドレス）からのログインの失敗は15分に10回まで、ゲストの作成は1時間に10回まで。超えたら「しばらくしてから再度お試しください」と表示する |
| U-11 | 退会 | ヘッダーのメニューから退会できる（画面は `screen-design.md` W-08）。確認ダイアログでパスワードを入力して本人か確かめ、正しければアカウントとすべてのデータ（ボード・リスト・カード・ラベル）を削除する。削除したあとはログイン画面に戻り、「退会しました」と表示する。ゲストには表示しない（ログアウトでデータが消えるため） |

入力ルール：

| 項目 | ルール |
|---|---|
| メールアドレス | メールアドレスの形式であること。254文字まで。大文字は小文字にそろえて保存する（`Taro@example.com` と `taro@example.com` は同じ人とみなす）。存在するアドレスかどうかの確認（確認メールの送信）はしない |
| パスワード | 8〜64文字。半角の英数字と記号のみ。英字と数字を両方含む、などの組み合わせのルールは付けない |

### 3.2 ボード

| ID | 機能 | 内容 |
|---|---|---|
| B-01 | ボード名 | ヘッダーにボード名を表示する。クリックすると名前を変更できる（1〜50文字）。初期値は「マイボード」 |

### 3.3 リスト

| ID | 機能 | 内容 |
|---|---|---|
| L-01 | リスト表示 | ボードにリストを左から順に並べて表示する |
| L-02 | リスト追加 | 名前（1〜50文字）を入力してリストを追加する。追加したリストは右端に並ぶ |
| L-03 | リスト名変更 | リストの名前を変更する |
| L-04 | リスト削除 | 確認ダイアログ（例：「このリストと中のカード3件を削除しますか？」）を出してから、リストと中のカードを削除する。リストは0個になってもよい |
| L-05 | リスト並び替え | ドラッグ＆ドロップでリストの順番を入れ替える |

### 3.4 カード

| ID | 機能 | 内容 |
|---|---|---|
| C-01 | カード追加 | リストの下の「＋ カードを追加」を押し、タイトルだけを入力して Enter で追加する。追加したカードはリストの一番下に並ぶ |
| C-02 | カード詳細 | カードをクリックすると詳細画面（モーダル）が開き、タイトル・説明文・重要度・緊急度・期限・ラベルを編集できる。「保存」ボタンでまとめて保存し、保存せずに閉じるときは確認する |
| C-03 | カード削除 | 詳細画面から、確認ダイアログを出してから削除する |
| C-04 | カード移動 | ドラッグ＆ドロップで、同じリスト内の並び替えと別のリストへの移動ができる |
| C-05 | 期限の表示 | カードに期限（例：10/30。年が違うときは 2027/1/5）を表示する。期限切れは赤、今日か明日が期限なら黄色にする。「今日」は利用者のブラウザの日付で判定する |
| C-06 | 重要度の表示 | カードの左端に色の帯を付ける（高＝赤、中＝黄、低＝灰色） |
| C-07 | ラベルの表示 | カードに付いているラベルを色付きで表示する |
| C-08 | 緊急度の表示 | 緊急度が「高」のカードにだけ「至急」の札（赤い文字＋赤い枠）を表示する。「中」「低」はカードには表示せず、カード詳細で確かめる |
| C-09 | 説明文の表示 | カードに説明文を3行まで表示する。3行を超えるときは「もっと見る」を押すと、カードの中で全文を開く。開いた状態は保存しない（再読み込みで閉じる） |

カードの項目：

| 項目 | 必須 | 内容 |
|---|---|---|
| タイトル | ○ | 1〜100文字 |
| 説明文 | | 2000文字まで。改行を反映して表示し、`http://`・`https://` で始まるURLはリンクにする（新しいタブで開く）。カードには3行まで表示する（C-09） |
| 重要度 | | 高・中・低。初期値は「中」。そのタスクがどれだけ大事か |
| 緊急度 | | 高・中・低。初期値は「中」。そのタスクをどれだけ急ぐか |
| 期限 | | 日付（時刻なし） |
| ラベル | | 複数付けられる |

### 3.5 ラベル

| ID | 機能 | 内容 |
|---|---|---|
| T-01 | ラベル管理 | ラベルを追加・名前変更・色変更・削除する。名前は1〜20文字で、同じユーザーの中で重複不可。色は用意した8色（`screen-design.md` 6章）から選ぶ |
| T-02 | ラベル付け | カード詳細画面で、カードにラベルを付けたり外したりする。1枚のカードに複数付けられる |
| T-03 | ラベル削除時の扱い | ラベルを削除すると、付いていたすべてのカードから外れる。カードは削除しない |

### 3.6 共通

| ID | 機能 | 内容 |
|---|---|---|
| G-01 | データ保存 | すべての操作をDB（PostgreSQL）に保存する。リロードしても状態が残る |
| G-02 | 入力チェック | 空のタイトルや長すぎる文字列などを受け付けず、エラーメッセージを表示する。画面側とサーバー側の両方でチェックする |
| G-03 | エラー表示 | 通信エラーやサーバーエラーが起きたら、画面にわかりやすく表示する |
| G-04 | 公開 | AWSにデプロイし、URLでアクセスできるようにする |

### 3.7 データ量の上限

いたずらでデータが増えすぎるのを防ぐため、全ユーザー（ゲストを含む）に次の上限を設ける。上限に達したら「リストは20個までです」のように表示する。数値は設定で変えられるようにする。

| 対象 | 上限 |
|---|---|
| リスト | 1ボードに20個まで |
| カード | 1リストに100枚まで |
| ラベル | 1ユーザーに30個まで（1枚のカードには、すべてのラベルを付けられる） |

## 5. 非機能要件

### 5.1 全般

| 項目 | 内容 |
|---|---|
| 時刻 | DBの日時はUTCで保存する。画面での日付の判定は利用者のブラウザの時刻を使う |
| 対応ブラウザ | Chrome・Edge・Safariの最新版 |
| 画面サイズ | PCでの利用が中心。スマートフォンでも表示が崩れず、リストを横にスクロールして見られる程度に対応する。スマートフォンでのドラッグ＆ドロップは必須にしない |

### 5.2 セキュリティ

Webアプリの代表的な脆弱性の一覧（OWASP Top 10）を一通りカバーする。

| 攻撃・リスク | 対策 |
|---|---|
| パスワードの漏えい | BCryptでハッシュ化して保存する |
| 通信の盗み見 | 本番の通信はHTTPSにする |
| SQLインジェクション | Spring Data JPA を使い、SQLを文字列の連結で作らない |
| XSS | React の自動エスケープに任せ、`dangerouslySetInnerHTML` は使わない。説明文のリンク化は `http://`・`https://` で始まるものだけにする |
| CSRF | Cookie `XSRF-TOKEN` とヘッダー `X-XSRF-TOKEN` でトークンを照合する（`api-design.md` 2.3） |
| セッションの乗っ取り | ログイン状態はセッション方式で管理する。Cookie に HttpOnly・Secure・SameSite を付け、ログイン時にセッションIDを変え、無操作30分で切る |
| 他人のデータの操作 | 毎回所有者を確認し、他人のデータには404を返す（U-05） |
| パスワードの総当たり | IPアドレスごとの回数制限（U-10） |
| クリックジャッキングなど | セキュリティ関係のHTTPヘッダーを付ける（他サイトへの埋め込み禁止、HTTPSの強制、読み込めるスクリプトの制限など） |
| 内部情報の漏えい | エラーの詳細（スタックトレース）を画面やAPIのレスポンスに返さない |
| 秘密情報の漏えい | パスワードなどの秘密情報はコードやGitに書かず、環境変数で渡す。本番ではAWSのパラメータ管理機能に入れる |
| ライブラリの脆弱性 | GitHub の Dependabot で、使っているライブラリの脆弱性の通知を受ける |
| DBへの直接攻撃 | DBはインターネットに公開せず、アプリのサーバーからだけ接続できるようにする。アプリ用のDBユーザーには必要な権限だけを与える |

### 5.3 性能

| 項目 | 内容 |
|---|---|
| 測る条件 | データ量が上限いっぱいのボード（リスト20個・カード2,000枚・ラベル30個）。同時に使う人は10人ほどと想定する |
| 目標 | ボードの表示（`GET /api/board`）は1秒以内。それ以外の操作（追加・保存・並び替えなど）は0.5秒以内 |
| 測り方 | AWSに公開した環境で、ブラウザの開発者ツール（Network タブ）でAPIの応答時間を見る |

### 5.4 運用

| 項目 | 内容 |
|---|---|
| AWSの予算 | 無料枠の範囲だけ。AWS Budgets で、料金が発生しそうなときにメールが届くようにする。無料期間が終わったら、公開をやめるか構成を見直す |
| バックアップ | DBを1日1回バックアップし、7日分残す（7日前までの状態に戻せる）。RDSを使う場合は自動バックアップ、EC2にPostgreSQLを置く場合は `pg_dump` で行う |
| ログ | 残すもの：エラー（500の原因）、ログインの成功・失敗、回数制限の発動、ユーザー登録・退会、すべてのAPIのアクセス（日時・URL・ステータス・処理時間）。ユーザーはIDで記録する |
| ログに残さないもの | パスワード、CSRFトークン、セッションID、メールアドレス、カードなどの中身 |
| ログの保存期間 | 14日。本番は CloudWatch Logs に送る |

### 5.5 テスト

| 対象 | 方法 |
|---|---|
| サーバー（Spring Boot） | JUnit で自動テストを書く。所有者の確認・並び順の振り直し・上限・入力チェック・ログインなど、間違えると困るルールを中心に確かめる。APIを実際に呼ぶ形のテストも書く |
| 画面（React） | 期限の色分け・URLのリンク化など、ロジックがある部分だけ Vitest で自動テストを書く |
| 画面全体 | テスト項目の一覧表を作り、公開の前に手動で確かめる |
| 自動実行 | GitHub Actions で、GitHub に push するたびに自動テストを実行する |

## 6. 技術スタック

| 区分 | 技術 |
|---|---|
| フロントエンド | React（Vite・TypeScript） |
| ドラッグ＆ドロップ | @hello-pangea/dnd（Trello のようなボード向け。リスト・カードの並び替えと別のリストへの移動、アニメーション、キーボード操作が標準で付いている。最後の更新は 2025年2月なので、使えなくなったらドラッグの部分だけ別のライブラリに入れ替える） |
| バックエンド | Java 25（最新のLTS） / Spring Boot（Gradle） |
| データベース | PostgreSQL 18 |
| 認証 | Spring Security（セッション方式。セッションは Spring Session JDBC で PostgreSQL に保存） |
| インフラ | AWS |
| バージョン管理 | Git / GitHub |

Java と PostgreSQL 以外のバージョンは、作り始めたときの最新の安定版を使う。実際に使っているバージョンの一覧は `detailed-design.md` 5.1 にまとめる。

## 7. 今回やらないこと

### 後回し（提出のあとに追加を検討する）

- 複数ボード
- パスワードの再設定（メール送信が必要なため）
- メールアドレス・パスワードの変更（退会は U-11 で対応する）
- カードの検索・絞り込み

### 対象外

- 重要度順・緊急度順・期限順の自動並び替え（ドラッグ＆ドロップで自分で並べる方式にしたため）
- チェックリスト
- リアルタイム同時編集（ほかの人の操作が即座に画面に反映される機能）
- ファイルの添付
- ボードの共有（メンバー招待）
